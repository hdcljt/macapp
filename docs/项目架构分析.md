## 1. 项目概述

### 1.1 项目定位

「算粒AI助手」是一个基于 **Electron + TypeScript** 的跨平台（macOS / Windows）AI 桌面客户端。它的本质是一个**桌面壳（Shell）应用**：

- 本身**不实现 AI 业务逻辑**，启动后加载远程 Web 应用（默认 `https://cloudrender-sche-test.migu.cn:10600/agent-user/assistant`，对应 deerflow agent-user 前端服务）；
- 核心价值在于提供**原生窗口体验**（自定义标题栏、窗口尺寸控制、任务栏标题带版本号）+ **可靠性工程**（离线兜底、重试、日志、自动更新）+ **安全边界**（导航拦截、外链接管）。

### 1.2 技术栈

| 层 | 技术 | 版本 |
|---|---|---|
| 桌面框架 | Electron | 43 |
| 语言 | TypeScript | 7（主进程）/ 5.8（offline-app） |
| 主进程构建 | esbuild（CJS bundle） | 0.28 |
| 离线页框架 | Vue 3 + Pinia + Element Plus | 3.5 / 3.0 / 2.9 |

## 2. 整体架构

### 2.1 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                       Electron 主进程 (main.js)                  │
│                                                                 │
│  app.whenReady()                                                │
│   ├─ initLogger()               ← userData/logs/main.log        │
│   ├─ loadConfig()               ← config.jsonc (bundled/user)   │
│   ├─ registerIpcHandlers(mode)  ← 按模式条件注册                  │
│   ├─ createMainWindow(config)   ← 双模式二选一                    │
│   └─ setImmediate → initUpdater + checkForUpdates               │
│                                                                 │
│  ┌─────────────── BrowserWindow (mainWindow) ─────────────────┐ │
│  │                                                            │ │
│  │  模式 A offline-first（默认）:                              │ │
│  │  ┌──────────────────┐    ┌──────────────────────────────┐ │ │
│  │  │ offlineView      │    │ contentView                  │ │ │
│  │  │ (本地 Vite 产物) │ ⇄  │ (远程 targetUrl, sandbox:off)│ │ │
│  │  │ sandbox: true    │    │ will-navigate 白名单拦截      │ │ │
│  │  └──────────────────┘    └──────────────────────────────┘ │ │
│  │                                                            │ │
│  │  模式 B legacy:                                            │ │
│  │  splash → retry → error + contentView（静态 HTML 页）       │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                 │
│  ┌──── updaterWindow (modal BrowserWindow, updater.html) ─────┐ │
└──────────────┬──────────────────────────────────────────────────┘
               │ contextBridge (preload.js)
               ▼
   window.electronAPI（versions / retry / retryOnline /
   onLoadingStateChange / log / updater.{download,install,dismiss,
   onProgress,onDownloaded,onError}）
```

### 2.2 进程与视图模型

项目采用 **BrowserWindow + 多 WebContentsView** 架构而非多 BrowserWindow 或单 webContents 路由：

- `mainWindow` 本身**不加载任何内容**，仅作为容器（原生标题栏 + 尺寸/事件管理）；
- 内容全部由叠加在 `contentView` 上的多个 `WebContentsView` 承载，`showOnly()` 保证**同一时刻仅一个可见**；
- 窗口 `resize` 时通过 `attachResizeHandler` 同步所有 view 的 bounds；
- dev 模式下 DevTools 挂到 `contentView`（生存期最长，随视图切换持续可用）。

### 2.3 两种视图策略（核心状态机）

由 `config.jsonc` 的 `useOfflineFallback` 字段切换（v0.6.0+ 默认 `true`）：

**模式 A — offline-first（默认，推荐）**

```
启动 ──→ 立即显示 offlineView（本地 Vite 产物，零网络依赖，秒开）
      └─ 异步加载 contentView(targetUrl)
           ├─ did-finish-load ──→ emitLoadingState('hide') → 切到 contentView
           └─ did-fail-load / render-process-gone
                 └─ 留在 offlineView，TopBar「重新连接」按钮可点重试
```

**模式 B — legacy（v0.5.6 兼容行为）**

```
启动 ──→ 显示 splash(loadingView)
      └─ 加载 contentView
           ├─ 成功 → 切到 contentView
           └─ 失败 → retryView（"正在重试 N/M…"）→ 间隔 retryDelayMs 后 reload
                 └─ 超过 maxRetries 次 → errorView（显示 targetUrl + 重试按钮）
```

### 2.4 职责边界（重要设计决策）

offline-fallback 系统**只负责「contentView 首次成功加载前」的兜底**。一旦切换到 contentView，后续的 reload 失败、渲染崩溃等由远端应用和 Chromium 自身处理，不会把用户踢回离线页——避免破坏正在使用的上下文。

## 3. Electron 主进程模块详解

### 3.1 `main.ts` — 入口与视图状态机（411 行）

**核心职责：**

| 职责 | 实现 |
|---|---|
| 视图创建 | `createView()`（本地 HTML，sandbox: true）/ `createUrlView()`（远程 URL，sandbox: false） |
| 视图互斥 | `showOnly(view)` 对 5 个 view 做排他显隐 |
| 窗口创建 | `createBaseWindow()`：尺寸来自配置、macOS `hiddenInset` 标题栏、标题固定为 `算粒AI助手 v{version}`（拦截 `page-title-updated` 防覆盖） |
| 安全拦截 | `attachContentViewCommonHandlers()`：`will-navigate` 仅放行 `allowedOriginPrefix`（由 targetUrl origin 推导）；`setWindowOpenHandler` 阻止新窗口、https 外链交给系统浏览器 |
| 失败处理 | 模式 A：只发 `hide` 事件、不动视图；模式 B：`attemptLegacyRetry()` 统一处理 `did-fail-load` 与 `render-process-gone` 两种失败源 |
| IPC 注册 | `registerIpcHandlers(mode)` **启动时一次性注册**（修复 macOS activate 重建窗口导致的 handler 累积泄漏），且按模式条件注册对应频道 |
| 防御性状态 | `loadFailed`（防 did-finish-load 覆盖失败视图）、`offlineReady`（防 IPC 早发丢失） |

**生命周期：** `whenReady` → 日志 → 配置 → IPC → 主窗口 → 延迟启动 updater（`setImmediate` 隔离，更新器异常不影响主流程）→ `activate` 重建窗口（macOS）→ `before-quit` 关日志。

### 3.2 `config.ts` — 配置系统（417 行）

**配置 schema（11 字段，全部必填）：**

| 字段 | 类型/约束 | 用途 |
|---|---|---|
| `targetUrl` | http(s) URL | contentView 加载地址，并推导导航白名单 |
| `maxRetries` | 整数 ≥ 0 | legacy 模式最大重试次数 |
| `retryDelayMs` | 整数 ≥ 0 | 重试间隔（毫秒） |
| `width` / `height` | ≥ min 尺寸 | 窗口初始尺寸 |
| `minWidth` / `minHeight` | ≥ 1 | 窗口最小尺寸 |
| `autoUpdate` | boolean | 是否启用更新检测 |
| `updateChannel` | 'stable' \| 'beta' | 更新通道 |
| `dismissCooldownHours` | 整数 ≥ 0 | dismiss 更新后的静默期 |
| `useOfflineFallback` | boolean | 视图策略开关（A/B 模式） |

**三层配置模型：**

```
dev 模式        → 仓库根 config.jsonc（开发者日常编辑）
生产首次启动    → bundled（安装包 Resources/）复制 → userData/config.jsonc
生产后续启动    → 优先读 userData（用户可编辑副本）
复制失败        → 降级只读 bundled（警告：编辑不持久化）
```

**关键实现细节：**

- **硬失败策略**：JSONC 解析错、字段缺失/类型错、targetUrl 不合法均 `process.exit(1)`，绝不默认值兜底（快速暴露问题而非带病运行）；
- **向后兼容迁移**：生产模式下检测用户 config 缺字段（如 v0.5.6→v0.6.0 升级缺 `useOfflineFallback`），从 bundled 补齐并用 `jsonc-parser` 的 `modify()`/`applyEdits()` **保留用户注释和缩进**地写回；写回失败时内存兜底；
- 错误类型体系：`ConfigNotFoundError` / `ConfigParseError` / `ConfigValidationError`，均带 configPath 上下文。

### 3.3 `logger.ts` — 日志系统（152 行）

零依赖自研（未用 electron-log），特性：

- **输出格式**：`2026-08-24T10:30:00.123 [LEVEL] [module] message`（本地时区 ISO 8601 毫秒精度）；
- **双写**：console + `userData/logs/main.log`（每次启动写 header，退出写 footer，含平台与 Electron 版本）；
- **轮转**：单文件 5MB 上限，`main.log` → `.1` → `.2` → `.3`，最多 3 个备份；
- **命名空间**：`logger.child('main')` 生成嵌套模块名（`app.main`、`app.config`、`app.updater`、`app.renderer`）；
- **渲染进程接入**：`registerLogHandlers()` 注册 `log:write` IPC handle，渲染页 console 输出统一落盘。

### 3.4 `updater.ts` — 在线更新（239 行）

基于 electron-updater + GitHub Releases（`hdcljt/macapp`）：

```
启动 checkForUpdates()
   ├─ 静默期内（dismiss 记录 + cooldown）→ 跳过
   └─ 发现新版 → showUpdateWindow(info)
        （独立 modal BrowserWindow 加载 updater.html，
         version/notes 经 URL query string 传递 —— sandbox 安全，
         替代不可靠的 additionalArguments）
             ├─ 用户「立即更新」→ autoUpdater.downloadUpdate()
             │     └─ 进度经 IPC 'updater:progress' 实时推送 → 进度条
             │           └─ 完成后 'updater:downloaded' → 「立即安装」
             │                 └─ quitAndInstall(false, true)
             └─ 用户「以后再说」→ dismiss 时间戳持久化到
                userData/updater-dismiss.txt（跨重启生效）
```

**平台差异**：Windows NSIS 支持 Squirrel 差分自动安装；macOS 因 ad-hoc 签名不支持增量更新，下载 DMG 后引导用户手动替换。

### 3.5 `preload.ts` — 安全桥（63 行）

以 `contextBridge.exposeInMainWorld('electronAPI', …)` 暴露最小 API 面：

- `platform` / `versions`（app 版本经 IPC `app:version` 获取，因打包后 `npm_package_version` 丢失）；
- `retry()`（legacy error 页）/ `retryOnline()`（offline 页 TopBar）；
- `onLoadingStateChange(cb)`：返回 **unsubscribe**，配合 Pinia store 在 Vite HMR 时清理 listener 防累积；
- `log(level, message)`：渲染日志落盘；
- `updater.*`：download / install / dismiss / onProgress / onDownloaded / onError。

所有 view（offline/splash/retry/error/updater 页）共用同一 preload，安全基线为 `contextIsolation: true` + `nodeIntegration: false`。

### 3.6 静态页（electron/static/）

| 文件 | 用途 | 被谁引用 |
|---|---|---|
| `splash.html` | legacy 启动动画 | 模式 B |
| `retry.html` | legacy 重试提示 | 模式 B |
| `error.html/.js/.css` | legacy 错误页（显示 targetUrl，重试按钮发 `retry:request`；targetUrl 经 URL query 传入） | 模式 B |
| `updater.html/.js/.css` | 更新对话框（版本号、Release Notes、进度条、立即更新/以后再说） | updater.ts |

## 4. 离线兜底应用（offline-app）

### 4.1 定位与技术选型

offline-first 模式的**首屏页面**：本地打包进应用的 Vue 3 SPA（无网络依赖），UI 复刻线上 `agent-user/assistant` 页面布局，让用户在离线时仍看到熟悉的界面。构建产物直接输出到 `dist-electron/offline-app/`，由主进程以 file:// 方式加载。

技术栈：Vue 3.5（Composition API + `<script setup>`）+ Pinia 3 + Element Plus 2.9 + Vite 8 + SCSS（无 Tailwind，颜色以 hex 直绑）。

### 4.2 页面结构（App.vue）

```
┌──────────────────────────────────────────┐
│ TopBar（菜单按钮 | 连接状态toast | 新建对话）│
├──────────────────────────────────────────┤
│ SideDrawer（v-model 抽屉，mock agent 列表）│
├──────────────────────────────────────────┤
│ AppCarousel（AI 应用横滑切换栏）           │
│   千问 / Kimi / 智谱 / MiniMax / 可灵 / Vidu│
│ ────────────────────────────────────     │
│ FeatureSection × 3（功能区块）             │
│   算粒写（脑图/PPT/纪要/代码）             │
│   算粒听（在线听/离线听/翻译/音乐）         │
│   算粒存（视频/笔记/文字/图片）             │
├──────────────────────────────────────────┤
│ BottomTabBar（写脑图/在线听/存视频/写代码） │
│ InputBar（输入 + 语音 + 相机 + 更多，占位） │
└──────────────────────────────────────────┘
```

所有交互（发消息、语音、拍照）在离线场景均为**占位实现**（console.log），仅 UI 状态（抽屉开关、激活 tab/app）真实生效。

### 4.3 连接状态展示（TopBar 三态）

TopBar 右侧 toast 实时反映主进程连接状态，数据来自 Pinia store：

| 状态 | 条件 | 展示 |
|---|---|---|
| skeleton | `hasReceivedFirstEvent === false`（启动瞬间，首条 IPC 未达） | 灰色脉冲占位块（防「重新连接」误显） |
| connecting | `isConnectingToOnline === true`（主进程正加载 targetUrl） | spinner + 「正在连接在线服务…」 |
| retry | 连接结束且未切走 | 「重新连接」按钮 → `retryOnline()` → IPC → 主进程 reload |

### 4.4 `stores/ui.ts` — 状态管理

纯 UI 状态：`drawerOpen` / `activeTabId` / `activeAppId` / `isConnectingToOnline` / `hasReceivedFirstEvent`。store 创建时订阅 `onLoadingStateChange`，并通过 `import.meta.hot.dispose()` 在 HMR 时退订，避免 listener 累积。

### 4.5 `electron-logger-bridge.ts` — console 桥

- 包装 console 5 个方法：先调原 console（保留 DevTools 输出），再异步 IPC 转发主进程落盘（模块名 `renderer`）；
- `Symbol.for()` 幂等标记防 Vite HMR 重复执行 IIFE 导致的**嵌套包装**（否则日志翻倍）；
- dev:offline（纯浏览器）模式无 `electronAPI` 时静默跳过；
- 参数序列化：string 直传 / Error 取 name+message / 其他 JSON.stringify 失败回退 String()。

## 5. IPC 通信契约汇总

| 频道 | 方向 | 模式 | 触发方 → 处理方 | 作用 |
|---|---|---|---|---|
| `online:loading` | main→renderer | A | main 推送，offline TopBar 订阅 | 'show'/'hide' 连接状态 |
| `online:retry` | renderer→main | A | TopBar「重新连接」→ main reload contentView | 用户手动重连 |
| `retry:request` | renderer→main | B | error 页「重试」→ 重置计数并 reload | legacy 重试 |
| `log:write` | renderer→main (invoke) | 全部 | 各渲染页 → logger 落盘 | 渲染日志收集 |
| `app:version` | renderer→main (invoke) | 全部 | updater 页 → app.getVersion() | 显示当前版本 |
| `updater:download` | renderer→main (invoke) | 全部 | updater 页 → downloadUpdate() | 开始下载 |
| `updater:install` | renderer→main (invoke) | 全部 | updater 页 → quitAndInstall() | 安装并重启 |
| `updater:dismiss` | renderer→main (invoke) | 全部 | updater 页 → 持久化 dismiss 时间戳 | 静默 N 小时 |
| `updater:progress` | main→renderer | 全部 | 下载进度百分比 | 进度条 |
| `updater:downloaded` | main→renderer | 全部 | 下载完成 | 显示「立即安装」 |
| `updater:error` | main→renderer | 全部 | 更新出错 | 错误提示 |

注册策略：`retry:request` 与 `online:retry` 按模式**条件注册**（对方模式下是死路径），且统一在启动时注册一次而非窗口创建时（防 macOS activate 泄漏）。

## 6. 构建体系与工程化

### 6.1 构建流水线

```
npm run build
 ├─ icon:generate        scripts/generate-icons.js（sharp：icon.png/.ico/.icns + iconset）
 ├─ build:electron       scripts/build-electron.js
 │    ├─ esbuild 打包 main.ts → dist-electron/main.js（CJS、node18、sourcemap）
 │    ├─ esbuild 打包 preload.ts → dist-electron/preload.js
 │    └─ 复制 9 个 static 文件（扁平结构，运行时 __dirname 直接引用）
 │       ※ mainFields:['module','main'] 解决 jsonc-parser UMD 动态 require
 │         无法内联的坑；electron-updater 被 inline（约 +200KB）
 ├─ build:offline       offline-app 内 npm install + vite build
 │    → 产物输出 dist-electron/offline-app/（base:'./' 相对路径，target chrome120）
 └─ electron-builder    cross-env ELECTRON_RUN_AS_NODE=0 + 平台目标
      ├─ files: dist-electron/** + package.json
      ├─ extraResources: build/icon.png + config.jsonc → Resources/
      ├─ mac: dmg+zip（x64/arm64/universal），ad-hoc 签名（identity:'-'）
      └─ win: nsis+zip（x64），中文快捷方式名
```

### 6.2 Windows 打包专项（Defender EPERM 规避）

`scripts/build-windows-installer.js` 针对 electron-builder 26 在 Windows 上被 Defender 锁文件的三个规避手段：

1. 预下载 Electron zip 并用 PowerShell `Expand-Archive` 解压到 `.electron-cache/electron`，配置 `electronDist` 让 builder 跳过自动解压；
2. NSIS 的 `.exe.tmp` 被锁时用 PowerShell `Copy-Item` 复制为最终 `.exe`；
3. `build-windows.js` 提供旧版便携 ZIP 兼容路径。

## 7. 关键设计决策与亮点

1. **offline-first 启动策略**：先秒开本地离线页再异步探测远端，实现「始终有可用 UI」；连接状态以 skeleton→connecting→retry 三态 toast 呈现，且用 `hasReceivedFirstEvent` 防「启动瞬间误显重连按钮」的竞态。

2. **多 WebContentsView 单窗口架构**：相较 BrowserView（已废弃）选用 WebContentsView；5 个视图排他显隐 + resize 同步，避免了多窗口管理的焦点/层级问题，也让本地页与远程页的 webPreferences 安全策略可以差异化（离线页 sandbox: true，线上页为兼容性 sandbox: false）。

3. **三层配置 + 保注释迁移**：bundled（出厂种子）→ userData（用户可编辑）→ dev（仓库根）分层；版本升级缺字段时用 JSON AST 级 `modify/applyEdits` 增量补齐，**保留用户注释与缩进**；全程硬校验快速失败。

4. **安全纵深**：contextIsolation + nodeIntegration:off 全视图统一；`will-navigate` 白名单锁定 targetUrl 同源；`window.open` 全拒、https 外链转系统浏览器；sandboxed renderer 中数据传递用 URL query string 而非 process.argv（updater 的 version/notes 即此实践）。

5. **全链路可观测**：主进程 + 5 类渲染页 console 统一落 `main.log`（带模块名 renderer）；console 桥用 Symbol 幂等防 HMR 嵌套包装；Pinia 订阅 unsubscribe + HMR dispose 配对，防 listener 泄漏。

6. **防御性工程细节**：`loadFailed` 标志防 did-finish-load 覆盖失败视图；`offlineReady` guard 防 IPC 早发丢失；`emitLoadingState` 前检查 webContents.isDestroyed()；updater 全部事件先判窗口存活再 send；IPC handler 启动期一次注册防 activate 累积；dismiss 时间戳落盘实现静默期跨重启。

7. **平台差异收敛**：macOS hiddenInset + trafficLightPosition 定制、`activate` 重建窗口、更新走手动 DMG；Windows NSIS 静默安装重启、Defender EPERM 规避脚本；标题带版本号便于运维排障（`app.getVersion()` 而非 `app.getName()` 规避 dev 名不一致）。

## 9. 总结

| 维度 | 评价 |
|---|---|
| **架构** | 清晰的「壳 + 远程内容 + 离线兜底」三层结构；主进程 4 个模块各司其职（视图/配置/日志/更新），总量约 1300 行 TS，复杂度可控 |
| **可靠性** | 双视图策略可切换、三级降级（复制失败读 bundled、更新器异常不影响主流程、离线页自身加载失败 2s 自愈重载） |
| **安全性** | Electron 安全清单基线全部满足（contextIsolation/sandbox/导航白名单/窗口拦截），sandbox 下数据传递方案正确 |
| **可维护性** | plans/specs/review 三层文档沉淀；关键坑（jsonc-parser UMD、Defender EPERM、additionalArguments 不可靠）均有注释沉淀 |
| **技术债** | legacy 模式与模式 A 存在少量复制粘贴（retry 逻辑两份）；static 旧页面在模式 A 下为死资源（README 已说明可删）；macOS ad-hoc 签名限制增量更新（预留正式签名升级路径） |

**一句话总结**：这是一个工程质量相当成熟的 Electron 桌面壳项目——业务全部外置（远程 URL + 本地离线页），自身聚焦于**配置、可靠性、安全、日志、更新**五项基础设施能力，并配套了完整的构建流水线与文档体系。
